Signal model#

TL;DR

  • A signal model is a Simulator subclass: a handler per kind of event, and a layout of one repetition.

  • The layout is the default description; a Pulseq file or an MRD stream can replace it, and the handlers still play every event.

  • Batching, derivatives, devices, estimation and design are written once against this interface.

You give blochsim a sequence and a tissue, and it returns the signal and its derivatives. The sequence is written once, as a signal model, and the 26 shipped simulators are written the same way as any you add.

Division of responsibility#

  • Gradient waveforms and spatial encoding, which belong to sequence design tools such as pypulseqpp. An event dephases by whole configuration orders.

  • The reconstruction encoding, which a model-based reconstruction takes from mri-nufft or bartorch.

  • Safety checks on gradients, PNS or SAR.

Method#

Handlers#

A handler is the operator for one kind of event, bound by a class attribute of that name. A pulse is played by the handler its Pulseq RF use names: excitation, refocusing, inversion, saturation, preparation or other, and a pulse with no use by excitation. An ADC event is played by readout and a wait by delay. A description carries no gradient events: a gradient is an action of the event it follows or precedes, so the handler decides, for example, whether a readout is followed by an unbalanced gradient, ideal spoiling or a rewinder. The built-in readouts SPGRReadout, SSFPFidReadout, bSSFPReadout and FSEReadout cover the four sequence families.

Layout#

layout takes the sequence parameters in milliseconds and degrees, and returns the operators of one repetition, built through self.operators, in seconds and radians. The first call builds the description; later calls rebind the numbers onto it. What is read from a file or stream is in Sequence description, and the tissue physics in Extended phase graphs.
